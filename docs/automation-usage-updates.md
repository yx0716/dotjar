# 可选定时捕捞、消耗展示与版本更新方案

状态：逐次消耗已随 v0.4.2 发布；实际范围见[消耗统计](usage.md)。定时捕捞、账号额度、每日汇总和导出仍为设计稿。更新机制已发布，使用方式和验证边界见 [安装与更新](updates.md)。日期：2026-11-11。

用户已确定：定时捕捞为可选项；消耗展示以用户能理解的额度为优先，不强求 token 口径。本文其余默认值为建议，实施时可调整。下面保留总体设计；已实现范围以安装与更新文档为准。没有开启后台模型调用；下文是完整目标设计，未实现的统计能力不能视为已交付。

## 1. 实施前的基础与缺口

- `src/core/session.js` 统一处理手动捕捞，但互斥只在单个进程内；网页服务与 Electron 可以各自调用模型。
- `src/core/distill.js` 支持 Claude CLI、Codex CLI、OpenAI 兼容接口。Claude 只取费用、耗时、模型；Codex 丢弃标准输出；兼容接口未读取 `usage`。
- `src/core/ledger.js` 的 `costUsd` 每次被覆盖，不是每天累计，也不是逐次账单。失败、取消和输出解析失败没有独立的用量记录。
- `src/service.js` 能管理后台服务与 macOS 登录自启。`src/server.js` 的旧代码提示依据本地文件修改时间，不会查找或下载新发布版本。
- 数据默认在 `~/.dotjar`，支持自定义数据目录和独立笔记目录。程序目前可能位于源码目录、全局 npm 目录或 npx 缓存；`package.json` 仍为 `private: true`。

## 2. 消耗展示：区分本次消耗与账号余量

页面统一入口叫「捕捞记录与消耗」。每次记录显示时间、手动/自动、模型、新增星星数、耗时、结果状态，以及能取得的消耗。示例数字仅用于说明：

| 可取得的数据 | 主界面文案示例 | 约束 |
|---|---|---|
| 服务商返回的本次 credits/计费单位 | 本次消耗 0.8 credits | 必须能关联到本次调用，并显示单位与来源 |
| 服务商返回的本次费用或工具计算费用 | 本次费用 $0.02 / 参考费用约 $0.02 | 区分实际费用、客户端估算；订阅登录不能称为额外扣费 |
| 只有本次 token 用量 | 本次处理 14.0k tokens | 详情展开输入、输出、缓存等，不能换算为订阅百分比 |
| 没有用量数据 | 本次消耗暂不可获取 | 未知不是 0；不按文字长度伪造精确值 |

账号额度单独放在模型选择处，例如「本周期已用 26%，18:00 重置」，附最近查询时间。周期名称、长度、重置时间都取服务商返回值，不硬编码成五小时或一周。不同账号、模型桶、计量单位不能直接相加。

**账号前后余额差不等于本次捕捞消耗。** 用户同时在 Claude/Codex 干其他工作，账号额度可能延迟更新、取整或跨重置窗口。即使查询到从 25% 到 26%，也只能展示账号快照变化，不能标成「本次用了 1%」。第一版不做这种归因估算。

适配器按能力实现，不承诺每家都有同样的统计：

- Claude：保留 JSON result 的累计 `usage`、`modelUsage` 与 `total_cost_usd`。官方说明后者是客户端费用估算，不能当作账单或订阅扣费；缓存读写要按它自己的语义归一化。[官方用量说明](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Codex：保留 `-o` 的正文输出，增加能力探测后的 `--json`，读取 `turn.completed.usage`。对多个事件按事件语义去重，不将累计值重复相加；旧版不支持时显示统计不可用。[非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)
- Codex 账号额度：另加可选的只读 app-server 适配器，使用受支持的账号接口；官方返回窗口已用比例、重置时间及部分账号的 credits 信息。它是账号级统计，不是本次调用账单。使用现有登录，不改登录状态，不调用购买或重置额度接口；版本、登录类型不支持则降级。[账号额度接口](https://learn.chatgpt.com/docs/app-server)
- OpenAI 兼容接口：从响应读取 `usage` 及返回的模型信息，接受字段缺失。官方 Chat Completions 有输入、输出、缓存与推理细分；第三方兼容服务需逐家核验，不能假定它们都有账户余额或同样价格。[响应结构](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
- Claude 订阅额度：本次未核实到适用于当前 CLI 的稳定逐次额度接口，首版不承诺。不得抓取内部网页接口来伪造稳定支持。

底层依然保存 token 原始统计，用于追溯，但不强迫用户阅读。统一字段中的输入总数包含缓存部分，输出总数包含该服务商计入输出的推理部分；缓存、推理细分不能再与总量相加。缺少必需分量时总量为未知。保留服务商原始用量字段和适配器版本，避免未来口径变化后无法解释。

新增 `<dataDir>/runs/<runId>.json`，每次尝试一份原子写入的记录，含：

- `runId`、批次 ID、目标工作日、触发来源、引擎、模型、程序版本、开始/结束时间。
- `status`：running / succeeded / failed / cancelled / interrupted；错误分类、实际新增星星数。
- `consumption`：数值、单位、reported / estimated / unavailable、数据来源、统计是否完整、可选价格表版本。
- `usage`：归一化 token 与受限的原始统计；不保存密钥、完整 prompt、完整 CLI 日志。
- `quotaSnapshot`：可选账号桶、周期、比例、重置时间、查询时间；与本次消耗分开。

发起模型调用前落记录，收到用量后先保存统计，再解析星星结果：模型输出格式错误也可能已经消耗额度。异常中止保留已知下限，显示「统计不完整」。重试是新 attempt，不覆盖失败记录。当天汇总含失败但已消耗的调用，并标明缺失统计的次数。历史记录不凭空补算。按月导出、按用户选择清理。

## 3. 定时捕捞：主动开启、控制次数、结果待确认

设置入口：「自动捕捞」开关，默认关闭。首次开启显示「会使用当前所选模型的额度，只生成候选，收下才写成笔记」。建议初始间隔 90 分钟，可选 60 / 90 / 120 分钟，每工作日最多自动尝试 4 次；手动捕捞独立显示，不计入自动次数上限。

后台调度器每分钟检查，依次满足：已开启 → 没在更新 → 达到间隔 → 未达次数上限 → 当前工作日有新材料 → 获得跨进程运行锁。没有材料不调用模型。初版以输入摘要指纹变化去重；可加最少新增对话数，但不把它作为唯一依据，因为长任务可能只产生一次新的最终回复。

- 目标按 `dayStartHour` 计算，明确传入工作日；不随网页当前选中的历史日期变化。后台完成后不强制切换用户正在浏览的页面。
- 初版继续沿用当天完整摘要，不宣称真正的增量推理。只有材料改变才执行，避免原样重复花费；后续再评估新片段加旧摘要的质量与费用。
- 手动和自动调用共用跨进程锁。网页多个标签、Electron、CLI 都遵守，防止重复消费；锁包含所有者、runId 和心跳，过期不能只凭一个 PID 就杀进程。
- 重启、睡眠恢复后重算计划，不补跑每一个错过的时间槽。已成功处理的材料指纹、自动尝试次数与退避时间持久化。
- 限流优先遵守服务商重置/重试时间；没有时间则指数退避。鉴权错误、额度耗尽、用户取消不盲目连续重试，展示暂停原因。每次实际模型尝试都计数。
- 开关关闭后停止排新任务；已开始的一次可完成，另提供明确的取消按钮。候选去重和用户已收下/略过的决定保持现有规则。
- 可选「额度不足时暂停自动捕捞」仅对可靠且新鲜的账号快照生效；未知状态不能显示为仍有额度。第一版以次数上限控制自动调用，费用/token 上限只能是启动前软限制，不能保证单次绝不超支。
- 设置展示下一次检查时间、最近一次结果、今日自动次数和暂停原因。休息回顾保持免费、本地读取，不与模型捕捞绑在一起。

## 4. 更新体验与安装布局

普通用户在「关于与更新」看到当前版本、最新版本、更新摘要，以及「检查更新」「更新并重启」「跳过此版本」。建议默认每天后台检查一次，可关闭；首次说明会联网获取发布信息。只查询版本，不上传对话、笔记或账号信息；网络请求仍会向托管方暴露普通连接元数据。下载和安装由用户点击触发，首版不静默安装。

优先支持 macOS 托管安装，保留 Node >=20 前提。使用 GitHub Releases 的固定版本制品，不依赖 npm 发布，也不拉取未发布的主分支。仍可一条命令安装，但该命令的最终格式等引导器完成后确定，避免文档先承诺不存在的命令。

```text
~/.local/share/dotjar/
  launcher/              稳定启动器与独立更新进程
  releases/<version>/    每个版本的不可变程序文件
  current.json           当前版本指针（原子替换）
  previous.json          最近一次健康版本
  staging/<jobId>/       尚未启用的下载与解包结果
  updates/<jobId>.json   更新事务状态及脱敏日志
~/.local/bin/dotjar      稳定入口
<dataDir>/              原有配置、台账、用量记录、休息状态、web-token
用户选择的笔记目录         独立保留，绝不作为版本文件处理
```

登录启动项指向稳定启动器，不绑定 npx 缓存或某一个 release 目录；明确记录 Node 绝对路径，启动前检查其存在和版本。Node 缺失时给出修复说明，首版不自动升级系统 Node。启动器自身的版本、更新协议和最低要求也受清单约束；不兼容时提示更新引导器，不强行用旧更新器执行新协议。

不同安装方式的处理：

| 来源 | 迁移策略 |
|---|---|
| 新普通用户 | 直接托管安装，以后在页面一键升级 |
| 现有 npm 全局 / npx 用户 | 手动运行一次迁移命令；复用原数据目录、端口和登录设置，再切到托管入口；说明旧命令可能仍指向旧版 |
| 源码 clone / worktree | 明示「开发版，源码由你管理」；只显示新版信息，提供另装托管版选项，不执行 git pull 或覆盖工作区 |
| 已安装且没有更新器的旧版本 | 必须先手动升级/迁移一次，无法凭新版发布让旧程序自动获得按钮 |

迁移前验证当前服务的来源与数据目录，仅停止确认属于本次迁移的实例。托管版与源码版若共用一个数据目录，只允许一个写入服务；隔离试运行则使用独立数据目录。Windows/Linux 暂保留手动升级路径，不能把 macOS 首版称为跨平台一键升级。

## 5. 更新事务、验证与回退

```text
检查新版 → 下载到 staging → 验证签名与兼容性 → 等待当前工作结束
        → 暂停写入 → 备份内部状态 → 停旧服务 → 切版本 → 启新服务
        → 健康检查通过：提交事务 / 失败：恢复旧版本并启动
```

下载期间旧服务照常运行。安装阶段设升级锁：停止自动捕捞，不接受新的捕捞和笔记写入；现有捕捞、文件写入和休息窗口结束后再切换，界面显示等待原因。所有写入入口包括 CLI 必须遵守；不强杀正在调用模型的任务。独立更新进程负责后续步骤，不能依赖即将被关闭的 HTTP 服务继续执行自己。

发布制品带版本清单：`version`、发布渠道、构建 commit、平台/架构、制品大小与 SHA-256、Node 范围、更新协议版本、最低启动器版本、可读写的数据 schema 范围、更新说明。用随启动器分发的可信公钥校验签名，再校验制品摘要；仅下载摘要文件不能证明来源。限制下载来源、大小、超时以及解包路径，禁止越界和链接逃逸；发行包预构建，运行时不执行任意安装脚本。签名密钥轮换要由现有可信密钥授权，不能把新公钥与下载物一起无条件信任。

原子切换前记录旧版本、数据位置和事务阶段。重启后健康检查核对版本、数据 schema、原端口与原授权、必要静态资源，以及隔离临时目录内的写入能力；不调用真实模型、不修改真实笔记。成功才记录新版本为健康，刷新页面。失败保留诊断、恢复指针和内部状态、启动旧版本；若旧版也启动失败，稳定启动器提供修复命令和日志位置。

**首版仅接受向后兼容的数据演进。** 新服务在健康检查完成前不开放业务写入。备份只涉及配置与内部台账，保留 web-token 文件权限；外部笔记不能因程序回退而恢复成旧内容。若未来有不可逆迁移，需要独立迁移发布和明确的恢复策略，不得沿用「自动无损回退」承诺。

进程异常退出或断电后，启动器按事务阶段恢复：切换前继续旧版；切换后未通过健康检查则回退。升级锁确保多标签点击、CLI 同时升级只创建一个任务。保留当前及上一个健康版本；只清理确认不再被进程使用的旧制品，清理失败不影响服务。

更新 API 沿用现有本机 token、来源校验与请求头要求：读取状态用只读接口，安装必须显式 POST。只接受已验证清单中的版本 ID，不接受任意 URL、路径或 shell 命令；界面不出现 sudo 提示。发现目录不可写时给出修复路径，不擅自提升权限。

## 6. 实施顺序与验收

1. **消耗账本和展示**：先接三种引擎已支持的统计；验证缓存不重复计数、未知值、失败仍有消耗、批量汇总、历史记录缺字段与不同单位。账号余量作为独立适配器追加，不阻塞主功能。
2. **最小更新链路**：固定版本发布、托管安装、稳定启动器、签名验证、更新状态界面、健康检查和回退；从两个测试 release 演练完整更新。发布流水线只在正式 tag/release 时产出制品，PR 验证不发布。
3. **可选定时捕捞**：基于运行账本和跨进程互斥接入；验证重启、睡眠、跨工作日、查看历史日期、多客户端、额度暂停与更新期间暂停。
4. **旧用户迁移与体验打磨**：保留数据、自启和书签地址；覆盖源码有未提交改动、npx 缓存消失、旧版 Node、磁盘满、断网、制品损坏、端口占用、启动失败、更新中断电。

涉及的实现模块：扩展 `distill.js` 适配器、`dotjar.js` 捕捞链路与 `session.js`；新增运行账本、调度器、安装识别器和独立更新器；改造 `service.js`、CLI、网页桥接与中英文文案；Electron 和网页共用统计与锁，不各写一套调度规则。未来 PR 正文需明确这些共用模块影响的三种引擎与两种界面，并区分 mock 验证和真实服务商验证。

首版不包含：跨服务商统一额度换算、订阅余额差归因、硬性精确费用封顶、自动购买额度、自动更新模型 CLI、自动覆盖源码、不可逆数据迁移、无 Node 的原生安装包。
