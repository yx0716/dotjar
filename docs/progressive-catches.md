# 后台捕捞与逐条预览

状态：开发分支已实现，尚未发布。日期：2026-11-11。

点击捕捞后，页面立即接收后台任务编号，不再等待一个数分钟的 HTTP 请求。原有总览、候选和已留下内容仍可浏览；已有候选可以继续收下或略过。底部显示经过时间，取消了「大概要半分钟到一分钟」的承诺。

模型每生成一张完整、校验通过的卡片，就在总览显示其标题，可点击阅读正文。它标为「临时结果」，本轮完整结果通过校验并保存后才能收下或略过；这之前可以复制。只展示完整对象，不尝试补齐半个 JSON 或半段正文。整轮失败后已有候选不受影响，当前进程中的临时结果仍可查看，明确标为本轮未完成。

## 三种后端

- **Codex**：使用私有 stdio `app-server` 连接，新建 `ephemeral: true` 的临时会话，沿用当前登录和模型选择。只读沙箱、禁止申请权限，从 `item/agentMessage/delta` 获取正文增量，从本轮临时会话的用量通知保存统计。不会把推理日志展示成星星。[协议说明](https://learn.chatgpt.com/docs/app-server)
- **旧版 Codex**：若在发送 `turn/start` **之前**无法建立兼容连接，退回 `exec`。一旦发送过 `turn/start`，无论失败或超时都不自动重新调用，以免重复消费。降级模式仍在后台运行，但要等完整输出后才能显示新卡片。
- **Claude**：能力探测后使用 `stream-json` / `--include-partial-messages`；只读取正文 delta，最终 result 用于解析和用量。没有该能力的旧版继续用普通 JSON 返回。
- **OpenAI 兼容接口**：使用 SSE，按完整事件读取内容和用量。接口若返回普通 JSON，也能继续处理。若服务不支持 `stream` / `stream_options`，在 `config.json` 的 `api` 中设置 `"stream": false`；不会失败后静默再发一次请求。

流式预览改善等待体验，不能保证模型总耗时变短。如果模型仍在思考、没有输出正文，或者只在最后一次性输出，暂时不会出现新卡片。原有总超时仍保留。

## 状态与数据边界

- 网页和 Electron 都使用 session 的 `startDistill` 与 `jobStatus`。约每秒查询一次当前任务，不重新扫对话来获取流式进度。
- 重复点击同一 session 的捕捞返回同一任务；关闭或刷新网页不会重复提交。任务启动响应丢失时先查询现有任务，不自动重试模型。
- 更新写入门控保持到整个后台任务结束，不能因为启动请求已返回就提前切版本。
- 临时卡片只存在当前服务进程的任务状态中，未写入笔记或日台账。重启服务后不能恢复半成品；已经取得的用量仍保存在独立运行记录中。
- 多日捕捞仍顺序执行；预览按当前处理日期显示，不能串到另一日期。整批的失败列表与逐次用量仍保留，但批量过程中失败那一天的临时卡片不会跨后续日期保留。
- 此功能没有增加跨进程模型互斥，也不自动恢复失败任务；CLI 的原有等待返回接口继续可用。
